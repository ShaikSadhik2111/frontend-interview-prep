# AI Day 1 — LLM Fundamentals & API Thinking

## Position in the 4-track plan

AI is a **45-minute parallel track**. The goal is not to become an ML researcher; it is to build practical AI-engineering knowledge that strengthens a frontend/product-engineering profile.

- ⚛️ React / Frontend — primary track
- 🧠 DSA — coding track
- 🤖 AI — differentiator + AI engineering track
- 🛠️ Production Project — application track

## Goal

Understand how an LLM application works before moving into RAG, tool calling, agents, and AI application architecture.

## 45-minute AI session

- 10 min — LLM mental model
- 10 min — tokens, context and model output
- 10 min — API request/response lifecycle
- 10 min — structured output, validation and prompting
- 5 min — interview recall

## Topics

- LLM vs traditional deterministic software
- system/developer/user instructions
- prompts and context
- tokens and context windows
- temperature and generation controls
- structured output
- hallucination
- latency and cost
- streaming
- validation and safety boundaries
- application code vs model responsibility

## Real-project task

For the AI Excel Processing Platform, define:

1. What information enters the model?
2. What information must never be sent?
3. What exact schema should the model return?
4. What does the backend validate?
5. What happens when the model fails?
6. Which rules must remain deterministic in application code?

## Time-saving rule

Do not memorize AI vocabulary.

For every concept, answer:

**What is it? → Why does it matter? → Where would I use it? → What can go wrong?**
