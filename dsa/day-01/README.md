# DSA Day 1 — Big-O + Arrays

## Position in the 4-track plan

DSA runs in parallel with React and AI. This is the **morning 1.5-hour coding track** for product-company interview preparation.

- ⚛️ React / Frontend — primary frontend track
- 🧠 DSA — coding-round track
- 🤖 AI — AI engineering track
- 🛠️ Production Project — practical engineering track

## Goal

Build the reasoning habits needed for coding interviews, not just memorize solutions.

Day 1 establishes:
- Big-O time complexity
- Big-O space complexity
- array traversal
- searching
- min/max
- frequency counting
- brute force vs optimized thinking
- edge-case analysis

## 90-minute DSA session

- 15 min — Big-O mental model
- 15 min — array traversal patterns
- 35 min — coding problems
- 15 min — complexity + edge-case analysis
- 10 min — explain solutions aloud

## Problems

1. Find maximum number.
2. Find minimum number.
3. Reverse an array.
4. Check whether a target exists.
5. Find the second-largest distinct number.
6. Build a frequency map.

## Required interview workflow

For **every** problem:

1. Restate the problem.
2. Clarify assumptions.
3. Identify edge cases.
4. Explain brute force if relevant.
5. Explain the optimized approach.
6. Code it.
7. Dry-run with an example.
8. State time complexity.
9. State auxiliary space complexity.
10. Explain why the approach is correct.

## Edge cases to consider

- empty array
- one element
- duplicate values
- all values equal
- negative values
- target absent
- target present at first/last position

## Time-saving rule

Do not spend the session typing boilerplate.

Use this sequence:

**Understand → attempt → dry-run → inspect reference → explain from memory → move on.**

The objective is interview reasoning and pattern recognition.
